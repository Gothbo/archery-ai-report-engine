# 无锚点引导：正文只说明缺锚点，建立动作与候选场次仅入教练附注区

阶段 1 报告在无锚点时无法出方向判定，但教练看不到「为什么」也看不到「怎么补」。本 ADR 决定：正文（两视图共读）显式说明「当前无锚点 → 本窗口不出方向判定」这一事实；而「从哪场次建立锚点」的动作与候选场次列表放入 `coach_extra.anchor_setup`，仅教练返回。

## Context

变化判定依赖锚点作参照系；阶段 1 收尾时发现绝大多数报告无锚点，level 段要么只描述滚动基线、要么落到「暂无可判定的水平对比」占位，教练无从得知需要主动建立锚点。锚点建立端点（`POST /athletes/{id}/baseline/anchor`）与记忆层逻辑早已存在，缺的是**可见性与入口**。

同时 ADR-0005 已确立「正文对教练与运动员完全一致，运维字段仅入 coach_extra」。锚点建立是教练动作，其候选场次属运维信息。

## Decision

- 正文 level 段：无锚点（且该弓种为窗口主弓种）时，输出固定文案说明「缺锚点 → 不出方向判定」，只陈述事实，不写操作指令（两视图一致）。
- `coach_extra.anchor_setup`（仅 coach）：`needs_anchor` / `primary_bow` / `candidates` / `reason`。候选场次限定**早于当前窗口起点**，按时间升序（赛季初/入队测试场次在前），上限 10 条。
- 候选需含该弓种记分箭且具备可比性元数据（`distance_m`/`mode_composition`），与锚点建立校验（A3）同源：候选过滤条件与 `create_anchor_snapshot` 的真值判定对齐（`distance_m>0` 且 `mode_composition` 非空），避免列出建立时必失败的「死候选」。
- 候选与建锚还须满足记分箭最小样本（`data_quality.min_shots_for_description`）：样本过小的场次作锚点噪声底过高，会拖累后续方向判定。候选过滤与 `create_anchor_snapshot` 同用此门槛，保持「候选 == 可建立」；窗口前存在场次但均不足门槛时，`reason` 显式说明原因，不误报「无候选场次」。
- 仅当「建立锚点确实能让本窗口出方向判定」时才引导。以下情形抑制引导（`needs_anchor=False`）并在 `reason` 说明真实原因，避免给出无效动作：降级期（`mdc_source=None`，判定本身未解锁）、样本不足（`gate_ok=False`）、数据存疑（分布存在结构性矛盾）。对应地，level 段在这些情形下也不输出「无锚点」文案，改出样本不足 / 数据存疑说明。
- 前端在教练视图的水平对比段之后渲染「建立锚点」卡片：候选下拉 + 建立按钮；建立成功后按当前窗口重生成报告。

## Considered Options

- 引导全放正文（含候选与按钮）：会把运维动作暴露给运动员，违反 ADR-0005。
- 只给 coach_extra、正文不提示：正文继续出现无信息占位，运动员与教练都读不到「为何无判定」。
- 候选不限时间（含窗口内场次）：教练可能选到当前窗口场次，导致差值恒为 0、误以为功能失效。
- 正文说明 + 教练附注区动作（选中）：兼顾共读信息与运维隔离，且候选语义与滚动基线「窗口前」时间语义一致。

## Consequences

- 候选为「窗口前」场次：若运动员首次训练即为当前窗口，则候选为空，引导显式说明「无早于本窗口的候选场次」，属真实空状态。
- 锚点建立只取目标弓种记分箭（ADR-0004）：同场次含多弓种时不混算，候选过滤（含该弓种记分箭）与之一致。
- 建立锚点后需重生成报告方可看到方向判定（前端自动触发），缓存由 `refresh=1` 绕过。
- 若后续要求「以当前窗口为基线供未来报告使用」，需扩展候选时间范围并重新审视本 ADR（属阶段 2）。

## 修订（2026-10-12）：无锚点试行方向提示

### Context

原决策下，真实数据（绝大多数运动员无锚点）的 level 段只描述滚动基线、不出任何方向信息，报告无法回答教练最关心的「这段是不是在进步」。锚点是强断言方向判定的**唯一参照系**，但不建立锚点就永远读不到方向，导致记忆系统的锚点入口在真实使用中形同虚设。

### Decision

- 仅在**试行口径期**（`change_caliber_trial=true`）且**无锚点**（该弓种为窗口主弓种、`anchor_dict is None`）时，level 段在「无锚点」说明之后追加一条**滚动基线方向提示**：以窗口前滚动基线（近 `rolling_window_shots` 支记分箭，按窗口起点截断）为参照，复用同一 TE/SWC 两级口径（`avgScore`）判定，文案固定标注「方向提示（试行口径，参考）」。
- 该提示**始终不产强断言判定词**（不得出现 `判定：进步/退步`）。达 `MDC95` 也只表述为「上升/下降 N 环，方向提示（试行口径，参考）」；超噪声底但未达 SWC 表述为「正常波动」；低于噪声底表述为「不出方向提示」。
- **锚点仍是强断言方向判定的唯一参照系**：有锚点时 level 段走锚点 MDC 判定并写入结论记忆；无锚点的方向提示**不写入 `conclusions`、不入结论记忆、不参与平台期/近期结论逻辑**（记忆判定为锚点专属）。
- 非试行期（`change_caliber_trial=false`）无锚点场景回落为原行为：只描述滚动基线（「水平描述，非判定」），不出方向提示；`mdc_source=None` 的降级期仍只描述不判定（ADR-0002 优先）。
- 实现：`BASELINE_RULE` 独立于 `RULES`（避免锚点分支遍历 `RULES` 时对 `avgScore` 重复判定）；`generator._baseline_hint` 生成提示；无锚点提示语按是否试行区分（`NO_ANCHOR_HINT` / `NO_ANCHOR_HINT_TRIAL`）。

### Consequences

- 试行口径的价值可被真实数据验证：教练在无锚点时也能读到带口径标注的方向提示，同时其「参考、可撤回」的措辞与锚点强断言判定保持清晰区分。
- 该提示为试行特性，**回退方式**：置 `config.json` 的 `change_caliber_trial=false` 即回落为只描述；口径版本 `report_caliber_version` 已递增（v3→v4）作废旧缓存。
- 风险：滚动基线参照与锚点参照不同源，可能给出与日后建立锚点后不一致的方向；故措辞强制带「试行口径，参考」并**不落记忆**，避免污染锚点判定的历史结论。
