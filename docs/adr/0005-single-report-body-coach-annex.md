# 单一报告体：正文统一，角色差异只留备注可见性与教练附注区

报告正文对教练与运动员完全一致——领导要求"同一份报告，运动员和教练都能看"，因此不按角色选择内容。仅保留两处必要例外：备注可见性（沿用 `notes_visibility`，运动员仅见 injury/goal）与运维字段（`anchor_rebuild_hint`、evidence 明细）移入 `coach_extra` 附注区、仅 coach 返回。

## Context

素材 P1-2 曾把"两视角正文一字不差"记为缺陷，并要求阶段 1"梳理教练 vs 运动员视角差异"。但该判断的前提与领导的产品要求相反：领导要的是两者共读的同一份报告，本就没打算区分。据此 P1-2 改判为刻意设计，阶段 1 不再追求视角内容差异。

## Decision

- 正文（`sections`）对 `view=coach` 与 `view=athlete` 完全一致。
- 角色差异仅两处：备注可见性（隐私边界，非报告内容差异）；运维字段入 `coach_extra`（仅 coach 返回）。
- `view` 语义收窄为"备注过滤 + 附注区开关"，不再影响正文段集合。

## Considered Options

- 按角色选段（原方案）：与领导"都能看的报告"要求冲突。
- 完全统一（含运维字段进正文）：会把"锚点该重建了"等运维信号暴露给运动员。
- 统一正文 + 教练附注区（选中）：满足共读要求，运维噪声不外泄，且复用现有 `coach_extra` seam。

## Consequences

- 阶段 1 验收标准删除"两视角应有差异"一条。
- `anchor_rebuild_hint`、evidence 明细的可见性由 `view` 控制。
- 若后续产品要求视角分化，需重新审视本 ADR（届时属阶段 2 范畴）。
