# 窗口多弓种：以主弓种为准，其余标注不计入

一个窗口内混入多弓种时，报告以箭数最多的弓种为准计算全部指标，其余弓种的箭不计入，并在 `data_integrity` 段显式标注"另有 X 箭为 Y 弓种，未计入"；报告体新增 `bow_type` 元数据字段。

## Context

运动员A 同时存在反曲弓与 `proj172`；原实现按窗口聚合不区分弓种，一旦混入即污染均环（P1-3）。config 已声明"不同项目基线不混用"。

## Decision

主弓种为准 + 显式标注不计入的其余弓种 + 报告体携带 `bow_type`。

## Considered Options

- 混算：跨项目污染均环，正确性风险。
- 强制按弓种拆报告：产出大量小样本报告，接口/UI 大改，超出阶段 1。
- 主弓种为准 + 标注（选中）：最小改动消除污染，用显式标注保持透明（与 ADR-0002 同构）。

## Consequences

- 窗口指标计算前须先确定主弓种并过滤。
- 报告契约新增 `bow_type` 字段，前端可展示"本报告项目"。
- 弓种隔离须贯穿下游：锚点/滚动基线按主弓种取（`latest_snapshot(..., bow_type)`），样本门槛的"训练次数"按主弓种过滤（仅统计贡献了主弓种箭的场次）——否则会出现"指标已隔离、比对基线/门槛未隔离"的半隔离状态，仍可能跨弓种污染判定。
